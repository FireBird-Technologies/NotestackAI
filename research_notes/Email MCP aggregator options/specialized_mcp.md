# Specialized email MCP servers

## Which official or credible open-source MCP servers exist now?

### Takeaway
The strongest vendor-official transactional-email MCPs are Resend, Mailgun, Postmark, and AWS's SES sample. The strongest provider-native mailbox MCPs are Google's Gmail server, Microsoft's Work IQ MCP, and Fastmail's server. For one self-hosted server spanning several mailbox providers, `mcp-ecc` and `tecnologicachile/mail-mcp` are more directly relevant than the single-vendor servers, but they are community projects and require a security/code review.

### Cited Findings
- **Resend — transactional sending plus inbound/contacts/broadcasts/domains; vendor-hosted or self-hosted.** Resend's official repository documents a hosted Streamable HTTP server at `https://mcp.resend.com/mcp`, browser OAuth, bearer API-key authentication for headless clients, and the same open-source package for local stdio or HTTP deployment. It says the MCP can send and receive emails and manage contacts, broadcasts, and domains. — [Official Resend repository](https://github.com/resend/resend-mcp/blob/main/README.md)
- **Mailgun — transactional/marketing sending and deliverability; self-hosted stdio.** Mailgun's official MCP integration supports sending individual or batch messages, delivery metrics, bounces/complaints, address/domain validation, and charts; Mailgun describes it as local and requiring a Mailgun account/API key. Its official `server.json` lists the npm package `@mailgun/mcp-server`, `MAILGUN_API_KEY`, US/EU region, and stdio transport. — [Mailgun integration page](https://www.mailgun.com/integrations/mcp-server/); [official repository descriptor](https://github.com/mailgun/mailgun-mcp-server/blob/main/server.json)
- **Postmark — transactional sending and operations; self-hosted stdio.** ActiveCampaign's official Postmark repository exposes 24 tools for single/batch sending, templates, message search, diagnostics, bounces, suppressions, stats, server information, and webhooks. It is configured with one `POSTMARK_SERVER_TOKEN` and default sender/message stream. The repository was active in 2026 and explicitly warns users to use the official repository after a malicious namesake package incident. — [Official Postmark MCP repository](https://github.com/ActiveCampaign/postmark-mcp); [Postmark's security notice and launch post](https://postmarkapp.com/blog/postmark-labs-teaching-ai-to-speak-email-with-our-new-mcp-server)
- **Amazon SES — transactional sending and SES administration; self-hosted sample, not production-ready.** AWS's sample exposes all public SES v2 actions, including simple/template sends, contacts, suppression lists, dedicated IP pools, and deliverability metrics. It uses the local AWS profile and Java 21, and AWS explicitly says it is not intended for production without an independent security and quality assessment. — [AWS sample repository](https://github.com/aws-samples/sample-for-amazon-ses-mcp); [AWS Messaging Blog](https://aws.amazon.com/blogs/messaging-and-targeting/use-ai-agents-and-the-model-context-protocol-with-amazon-ses/)
- **Gmail — mailbox access and draft creation; Google-hosted developer preview.** Google's official endpoint is `https://gmailmcp.googleapis.com/mcp/v1`; the published tool set can search/read messages and threads, list labels/drafts, change labels, and create a draft, but it does **not** list a send tool. It requires the Google Workspace Developer Preview Program and Google Cloud/Gmail MCP API setup. — [Gmail MCP reference](https://developers.google.com/workspace/gmail/api/reference/mcp); [configuration guide](https://developers.google.com/workspace/gmail/api/guides/configure-mcp-server)
- **Microsoft Work IQ — Microsoft 365 mailbox and broader work data; Microsoft-hosted.** Microsoft's MCP can `fetch /me/messages` and `do_action /me/sendMail`, and also covers calendars, Teams chats, files, people, sites, and Copilot-backed retrieval through a single endpoint. It authenticates with Microsoft Entra ID; Microsoft notes tenant/service-principal setup and administrator involvement may be required. The docs were updated October 13, 2026. — [Work IQ MCP overview](https://learn.microsoft.com/en-us/microsoft-365/copilot/extensibility/work-iq/mcp/overview); [official Work IQ repository](https://github.com/microsoft/work-iq)
- **Fastmail — mailbox/calendar/contacts; Fastmail-hosted.** Fastmail launched `https://api.fastmail.com/mcp` in April 2026. A user adds the endpoint, completes OAuth, and the AI client can read and act on mail, calendar, and contacts; Fastmail gives drafting a reply as an example. — [Fastmail announcement](https://www.fastmail.com/blog/an-mcp-server-for-fastmail/)
- **`mcp-ecc` — multi-provider, multi-account, multi-user mailbox server; community/self-hosted.** Its 2026 changelog documents Google/Gmail, Microsoft Graph mail, Zoho Mail, and generic IMAP/SMTP providers; SQLite/D1 storage; OAuth flows; namespaced mail/calendar/contact tools; Docker/CLI/HTTP deployment; per-user bearer API keys; user-scoped accounts; and per-account OAuth clients. Version 0.3.0 added multi-user auth and per-user MCP keys, and later changes describe a single-container UI/API/MCP deployment and continued 2026 activity. — [Project changelog](https://github.com/karljsamuel/mcp-ecc/blob/main/Changelog.md)
- **`tecnologicachile/mail-mcp` — multi-provider, multi-account mailbox server; community/self-hosted.** The active 2026 Rust project supports IMAP/SMTP, Exchange Web Services, and Microsoft Graph, provider/account-specific configuration, OAuth2, attachments, and optional Streamable HTTP. Its own release notes state that HTTP has **no built-in authentication** and must remain on loopback or sit behind an authenticating gateway. — [Project repository](https://github.com/tecnologicachile/mail-mcp)
- **SendGrid — no official action MCP found.** Twilio's official MCP only indexes public API specifications/docs and does not execute SendGrid operations; OpenAI's official Twilio/SendGrid setup material explicitly says no Twilio MCP tools wrap SendGrid. The currently available action servers are community projects; for example, `deyikong/sendgrid-mcp` says it is maintained independently by a SendGrid engineer, not an official SendGrid product. — [Twilio MCP documentation](https://www.twilio.com/docs/ai/mcp); [OpenAI SendGrid setup skill](https://github.com/openai/plugins/blob/main/plugins/twilio-developer-kit/skills/twilio-sendgrid-account-setup/SKILL.md); [community SendGrid MCP](https://github.com/deyikong/sendgrid-mcp)

### Inferences
- For a product that merely needs reliable outbound application email from several owned domains, Resend or Mailgun is a lower-complexity choice than mailbox OAuth: one vendor account can verify multiple sending domains, while the MCP exposes sending/delivery operations. This is an architectural inference from the vendors' domain/account-level tools and API-key models. — [Resend repository](https://github.com/resend/resend-mcp/blob/main/README.md); [Mailgun MCP page](https://www.mailgun.com/integrations/mcp-server/)
- For access to users' existing inboxes across Gmail, Microsoft 365, Zoho, and arbitrary domains, `mcp-ecc` is the closest specialized open-source match to “one server for many email providers,” but it is much newer and less vendor-backed than the official Gmail/Work IQ/Fastmail endpoints. — [mcp-ecc changelog](https://github.com/karljsamuel/mcp-ecc/blob/main/Changelog.md)

### Gaps
- Vendor pages do not consistently publish MCP-specific uptime/SLA terms or independent production-adoption data.
- Fastmail's announcement describes read/action access and OAuth but does not publish a complete tool inventory on that page, so exact send/attachment capabilities should be verified with `tools/list` during evaluation. — [Fastmail announcement](https://www.fastmail.com/blog/an-mcp-server-for-fastmail/)

## What protocols/providers do they support?

### Takeaway
Transactional MCPs send through the vendor's own delivery network and do not provide general Gmail/Outlook mailbox access. Provider-native MCPs expose one mailbox ecosystem. Generic IMAP/SMTP or multi-provider Graph/API projects are the only specialized route to one interface across unrelated email domains and mailbox hosts.

### Cited Findings
- Resend, Mailgun, Postmark, and Amazon SES are delivery-platform MCPs: their documented tools focus on sending, domains/templates/contacts, delivery statistics, suppressions/bounces, and related account administration rather than synchronizing arbitrary end-user Gmail or Outlook inboxes. — [Resend](https://github.com/resend/resend-mcp/blob/main/README.md); [Mailgun](https://www.mailgun.com/integrations/mcp-server/); [Postmark](https://github.com/ActiveCampaign/postmark-mcp); [AWS SES sample](https://github.com/aws-samples/sample-for-amazon-ses-mcp)
- Google's MCP is Gmail-only and its current tool list is read/search/labels/drafts; it cannot be treated as a universal email sender or generic SMTP endpoint. — [Gmail MCP tool reference](https://developers.google.com/workspace/gmail/api/reference/mcp)
- Work IQ is Microsoft 365/Graph-backed and can read and send Outlook mail, with the benefit of related Microsoft 365 data and tenant policy. — [Microsoft Work IQ MCP overview](https://learn.microsoft.com/en-us/microsoft-365/copilot/extensibility/work-iq/mcp/overview)
- Fastmail's endpoint covers Fastmail mail, calendar, and contacts through OAuth. — [Fastmail announcement](https://www.fastmail.com/blog/an-mcp-server-for-fastmail/)
- `mcp-ecc` implements Gmail/Google, Microsoft Graph/M365, Zoho, and generic IMAP (read/search/manage) plus SMTP (send) behind common tools. Its changelog notes Cloudflare Workers only support HTTP-API providers, because IMAP is not available there. — [mcp-ecc changelog](https://github.com/karljsamuel/mcp-ecc/blob/main/Changelog.md)
- `mail-mcp` supports IMAP/SMTP, Microsoft Graph, and Exchange Web Services, and explicitly documents provider-aware behavior for Gmail, Zoho, Office 365, iCloud, and generic SMTP servers. It can run over stdio or optional HTTP. — [mail-mcp repository](https://github.com/tecnologicachile/mail-mcp)
- A newer Rust project, `zavora-ai/mcp-email`, advertises five send backends (SMTP, SES, SendGrid, Gmail API, Microsoft Graph) and three read backends (IMAP, Gmail API, Microsoft Graph), but it had only one GitHub star when inspected and its own table marked SendGrid and Microsoft Graph as “Ready” rather than tested; it is therefore a lower-confidence candidate. — [Project repository](https://github.com/zavora-ai/mcp-email)

### Inferences
- “Multiple email domains” has two different meanings: (1) sending from many domains the application owns, where Resend/Mailgun/Postmark/SES fit; or (2) acting inside many users' existing inboxes, where Gmail/Work IQ/Fastmail/IMAP/SMTP or a unified server like `mcp-ecc` is needed. The products should not be compared as interchangeable. — [Resend](https://github.com/resend/resend-mcp/blob/main/README.md); [Gmail](https://developers.google.com/workspace/gmail/api/reference/mcp); [mcp-ecc](https://github.com/karljsamuel/mcp-ecc/blob/main/Changelog.md)
- Generic IMAP/SMTP offers the broadest domain/provider coverage, but Graph or native APIs are still needed where basic authentication is disabled and for richer concepts such as threads, labels, drafts, and tenant policy. `mcp-ecc` explicitly moved Microsoft 365 to OAuth/Graph only as SMTP basic auth is retired. — [mcp-ecc changelog](https://github.com/karljsamuel/mcp-ecc/blob/main/Changelog.md)

### Gaps
- No single vendor-official specialized MCP found in this review natively unifies Gmail, Microsoft 365, Zoho, Fastmail, and arbitrary IMAP/SMTP accounts under one commercial SLA.

## What authentication and multi-account limitations exist?

### Takeaway
Most official specialized MCPs authenticate to one vendor account or one user's mailbox per connection. Resend's HTTP mode is unusually easy to place behind a shared endpoint because each request/client can carry its own API key. True multi-user mailbox tenancy requires a purpose-built server such as `mcp-ecc` or an integration platform; `mail-mcp` is multi-account but not safely multi-tenant over HTTP without an external gateway.

### Cited Findings
- Resend's hosted server supports user OAuth or bearer API keys. In self-hosted HTTP mode, each connecting client supplies its own Resend API key, and the package can be embedded as a library; local stdio configuration normally supplies one key. — [Resend repository](https://github.com/resend/resend-mcp/blob/main/README.md)
- Mailgun's official package configuration takes a single Mailgun API key and region per process over stdio. — [Mailgun server descriptor](https://github.com/mailgun/mailgun-mcp-server/blob/main/server.json)
- Postmark takes one server token and default sender per process. A Postmark account can have multiple servers, but the documented MCP configuration binds a process to the configured server token; separate tokens/processes or a custom credential router would be needed for isolated tenants. — [Postmark MCP repository](https://github.com/ActiveCampaign/postmark-mcp)
- AWS's sample uses the environment's AWS profile, so the active AWS account/role determines which SES identities and regions it can operate; the sample does not implement SaaS-style end-user OAuth or credential routing. — [AWS SES sample](https://github.com/aws-samples/sample-for-amazon-ses-mcp)
- Google's remote Gmail MCP is user-authorized and gated by the Workspace Developer Preview and Google Cloud project/API configuration. Its current public tool set does not send mail. — [Gmail configuration guide](https://developers.google.com/workspace/gmail/api/guides/configure-mcp-server); [tool reference](https://developers.google.com/workspace/gmail/api/reference/mcp)
- Work IQ uses Microsoft Entra ID discovery and tenant policy; administrative consent/service-principal provisioning may be necessary. Access remains permission-aware to the signed-in user's Microsoft 365 resources. — [Work IQ overview](https://learn.microsoft.com/en-us/microsoft-365/copilot/extensibility/work-iq/mcp/overview); [Work IQ repository](https://github.com/microsoft/work-iq)
- Fastmail authorizes the connection through an OAuth consent screen against the user's Fastmail account. — [Fastmail announcement](https://www.fastmail.com/blog/an-mcp-server-for-fastmail/)
- `mcp-ecc` supports multiple users, per-user MCP API keys, user-scoped accounts, per-account OAuth clients, encrypted stored credentials/tokens, and Google/Microsoft/Zoho OAuth plus app-password IMAP/SMTP. — [mcp-ecc changelog](https://github.com/karljsamuel/mcp-ecc/blob/main/Changelog.md)
- `mail-mcp` supports several configured accounts, but its optional HTTP endpoint has no built-in client authentication; the project says to keep it on loopback or put it behind an authenticating gateway. Thus it is multi-account, not an out-of-the-box multi-tenant SaaS service. — [mail-mcp repository](https://github.com/tecnologicachile/mail-mcp)

### Inferences
- A multi-tenant product should not expose a shared transactional MCP process with one global API key unless every tenant is intentionally sharing the same sending account and audit boundary. Per-tenant bearer keys (Resend HTTP), isolated processes, or a credential-routing layer are safer patterns. — [Resend HTTP authentication design](https://github.com/resend/resend-mcp/blob/main/README.md)
- If the user's `OutboundMcpConnections` feature stores one connection per end user, connecting users directly to official Gmail/Work IQ/Fastmail endpoints gives the cleanest vendor OAuth boundary, while a unified self-hosted server requires the application to own token storage, encryption, account routing, and revocation. — [Gmail setup](https://developers.google.com/workspace/gmail/api/guides/configure-mcp-server); [Work IQ authentication](https://learn.microsoft.com/en-us/microsoft-365/copilot/extensibility/work-iq/mcp/overview); [mcp-ecc changelog](https://github.com/karljsamuel/mcp-ecc/blob/main/Changelog.md)

### Gaps
- The reviewed official pages do not describe a turnkey model where one OAuth application transparently connects arbitrary Gmail, Microsoft, Fastmail, and IMAP users through one vendor-neutral MCP endpoint; that capability is generally offered by broad integration platforms or unified-email APIs rather than these specialized servers.

## Which would complement or beat a broad aggregator for the likely use case?

### Takeaway
Use Resend first if the requirement is “send product/transactional email from several owned domains”; it has the cleanest official hosted remote MCP plus self-hosting and per-client API-key support. Use official Gmail/Work IQ/Fastmail endpoints when users want agents to act in their real mailboxes. Use `mcp-ecc` only when the core differentiator is one self-hosted multi-provider mailbox interface and the team is willing to own security and operations.

### Cited Findings
- **Best simple outbound choice: Resend.** It is the only reviewed transactional vendor with both an official hosted OAuth MCP endpoint and the same open-source server for local/HTTP use, and it covers send/receive, contacts, broadcasts, domains, and per-client bearer keys. — [Resend repository](https://github.com/resend/resend-mcp/blob/main/README.md)
- **Best deliverability/operations alternatives: Mailgun or Postmark.** Mailgun's server emphasizes sending, domain validation, bounces/complaints, and performance analytics; Postmark exposes a deeper operational surface across templates, delivery diagnosis, suppressions, stats, and webhooks. Both are vendor-specific and local/API-key based. — [Mailgun integration](https://www.mailgun.com/integrations/mcp-server/); [Postmark repository](https://github.com/ActiveCampaign/postmark-mcp)
- **Best AWS-native choice: SES sample, after hardening.** It exposes all SES v2 operations and fits teams already using AWS IAM and SES, but AWS calls it a non-production sample. — [AWS SES sample](https://github.com/aws-samples/sample-for-amazon-ses-mcp)
- **Best mailbox-native choices: Gmail, Work IQ, Fastmail.** They keep authorization and data governance with the mailbox provider, but require one provider-specific connection each; Gmail's preview currently creates drafts rather than sends, while Work IQ can send. — [Gmail reference](https://developers.google.com/workspace/gmail/api/reference/mcp); [Work IQ overview](https://learn.microsoft.com/en-us/microsoft-365/copilot/extensibility/work-iq/mcp/overview); [Fastmail announcement](https://www.fastmail.com/blog/an-mcp-server-for-fastmail/)
- **Best open-source unifier to evaluate: `mcp-ecc`.** It is explicitly multi-user and multi-account across Gmail, Microsoft 365, Zoho, and IMAP/SMTP, with per-user keys and encrypted storage; however, its rapid 2026 development and community ownership mean it should undergo code review, penetration testing, dependency pinning, and operational hardening before production. — [mcp-ecc changelog](https://github.com/karljsamuel/mcp-ecc/blob/main/Changelog.md)
- **Security warning for all email MCPs.** Postmark had to warn users about a malicious namesake npm package that BCC'd messages; its official post directs users to the ActiveCampaign repository. This makes package provenance, pinned versions, least-privilege scopes, send confirmation, and egress/audit controls material selection criteria. — [Postmark official warning](https://postmarkapp.com/blog/postmark-labs-teaching-ai-to-speak-email-with-our-new-mcp-server)

### Inferences
- A broad aggregator beats specialized MCPs when the product needs delegated OAuth for many unrelated SaaS providers, standardized tenant onboarding, and managed token refresh. A specialized MCP beats the aggregator when the scope is one email delivery vendor, deeper vendor-specific operations matter, or the team wants lower per-action platform overhead and direct ownership of credentials. This follows from the single-vendor versus multi-provider boundaries documented above.
- Recommended evaluation order for the likely app: (1) Resend remote MCP for owned-domain outbound mail; (2) official Gmail + Work IQ connections for end-user mailbox access; (3) `mcp-ecc` proof of concept only if a single cross-provider endpoint is a hard requirement; (4) Mailgun/Postmark/SES when their delivery ecosystem or existing account footprint is already preferred.

### Gaps
- The final recommendation depends on whether “other email domains” means customer mailboxes (delegated inbox access) or application-controlled sending domains. The two lead to different architectures and should be confirmed before implementation.
- Pricing was intentionally not compared here because this subtask covers specialized servers, and MCP packages are often free while the underlying email service/account usage is billed separately; current vendor pricing needs a separate, plan-specific check.
